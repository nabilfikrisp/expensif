# Implementation status

## Target vs actual

`open` means the maintainer has not decided which side changes. `target decided` means an explicit maintainer decision requires the implementation to change. Existing target wording alone does not authorize agents to settle a difference or implement a fix.

| Area                              | Target or unresolved question                                                                                                                  | Actual                                                                                                            | Decision state | Evidence                                                                                                                                                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expense ingestion                 | Resolve linked owner and save immediately                                                                                                      | The expense command parses and displays one object; no linking check or message/expense writes                    | open           | [Bot controller](../server/src/modules/expense/controllers/bot.ts), [service](../server/src/modules/expense/service.ts)                                                                                     |
| Multiple items | Multiple expenses per message | One parsed object | open | [Parser](../server/src/modules/expense/parser.ts) |
| Categories                        | [Chosen fallback is `other`](product-intent.md#why-a-particular-fallback-category); global categories classify expenses                        | Hardcoded categories include `other`; category rows are not integrated or seeded                                  | target decided | [Expense service](../server/src/modules/expense/service.ts), [category schema](../server/src/modules/category/schema.ts)                                                                                    |
| Refresh sessions and logout       | [Current-session logout](product-intent.md#why-a-particular-logout-scope) revokes the associated refresh session; access JWTs expire naturally | Refresh sessions are not tracked; previously issued refresh JWTs remain valid, and logout only clears cookies     | target decided | [Auth service](../server/src/modules/auth/service.ts), [logout controller](../server/src/modules/auth/controllers/http/logout.ts)                                                                           |
| Access-token lifetime             | [5-minute target](session-revocation.md#token-lifetimes)                                                                                       | Default is 15 minutes; configuration can override it                                                              | target decided | [Configuration schema](../server/src/pkg/env/index.ts), [token signing](../server/src/modules/auth/service.ts)                                                                                              |

Refresh and CSRF cookie lifetimes are fixed at 7 days.          | target decided | [Configuration schema](../server/src/pkg/env/index.ts), [cookies](../server/src/pkg/cookies/index.ts)                                                                                                       |
| Deleted users during refresh      | Decide whether refresh must reject deleted users; see [unresolved session details](session-revocation.md#details-still-to-define)              | Refresh does not check whether the user still exists                                                              | open           | [Auth service](../server/src/modules/auth/service.ts)                                                                                                                                                       |
| Validation responses              | Shared error schema specifies `{success, message, error}` with string fields                                                                   | Validation responses differ from the declared shared envelope     | open           | [Shared schema](../server/src/shared/response.schema.ts), [login route](../server/src/modules/auth/controllers/http/login.ts)                                                          |

## Known gaps

These observations are not assigned backlog work. The maintainer chooses which to schedule; scheduled items belong in [backlogs](backlogs/) and receive a link here.

| Gap                                                                                                                           | Evidence                                                                                                                                                               |
| ----------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A key-containing message in a non-private chat is not deleted after key revocation. | [Controller](../server/src/modules/linked-account/controllers/bot.ts) |
| Expense failures expose the error message to Telegram users.                                                                  | [Expense bot controller](../server/src/modules/expense/controllers/bot.ts)                                                                                             |
| Parser category accepts arbitrary strings; descriptions are not validation. | [Parser](../server/src/modules/expense/parser.ts) |
| Production database setup does not pass a connection timeout; test setup passes one.                                          | [Composition root](../server/src/index.ts), [DB factory](../server/src/pkg/db/index.ts), [test helper](../server/src/test/helper.ts)                                   |
| Browser cookie visibility and refresh flow are not browser-tested.                                                            | [Auth tests](../server/src/test/modules/auth/) assert request/response headers                                                                                         |
| Logging redaction and escaped-string handling lack permanent regression coverage.                                             | [HTTP logger](../server/src/pkg/http/logger-middleware.ts), [test tree](../server/src/test/)                                                                           |
| Telegram command behavior and continued processing after update errors lack permanent coverage. Startup coverage is separate. | [Command wiring](../server/src/index.ts), [bot boundary](../server/src/pkg/bot/telegram/index.ts), [startup check](../server/src/test/pkg/bot/telegram/start.check.ts) |
| Runtime ingestion and duplicate-expense prevention remain unimplemented and untested; source-row uniqueness is covered. | [Expense service](../server/src/modules/expense/service.ts), [source tests](../server/src/test/modules/message/schema.test.ts) |
| Move standalone schema coverage into service or use-case tests when ingestion persistence exists. | [Backlog item](backlogs/p3-move-ingestion-schema-tests-to-persistence-tests.md) |
| HTTP logging buffers bodies before rate limiting and leaves valid JSON unbounded. | [Logger](../server/src/pkg/http/logger-middleware.ts); [backlog](backlogs/p1-bound-http-logging-work.md) |
| Authentication converts unexpected verification failures into client errors. | [Middleware](../server/src/modules/auth/controllers/middleware.ts), [refresh](../server/src/modules/auth/service.ts); [backlog](backlogs/p2-preserve-unexpected-authentication-errors.md) |
| Production and tests assemble application dependencies and routes independently. | [Entry point](../server/src/index.ts), [test helper](../server/src/test/helper.ts); [backlog](backlogs/p2-share-application-assembly-with-tests.md) |
| Domain errors carry HTTP status policy shared with non-HTTP consumers. | [Linked-account errors](../server/src/modules/linked-account/error.ts); [backlog](backlogs/p3-map-domain-errors-at-http-boundary.md) |
| Public response schemas inherit database columns through exclusion lists. | [API-key response schema](../server/src/modules/api-key/zod-schema.ts); [backlog](backlogs/p3-decouple-public-response-schemas-from-database-columns.md) |
