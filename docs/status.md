## Target vs actual

`open` means the maintainer has not decided which side changes. `target decided` means an explicit maintainer decision requires the implementation to change. Existing target wording alone does not authorize agents to settle a difference or implement a fix.

| Area                              | Target or unresolved question                                                                                                                  | Actual                                                                                                            | Decision state | Evidence                                                                                                                                                                                                    |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expense ingestion                 | Resolve linked owner and save immediately                                                                                                      | The expense command requires a linked user and displays one parsed object; no message/expense writes                    | open           | [Bot controller](../server/src/modules/expense/controllers/bot.ts), [service](../server/src/modules/expense/service.ts)                                                                                     |
| Multiple items | Multiple expenses per message | One parsed object | open | [Parser](../server/src/modules/expense/parser.ts) |
| Categories                        | [Chosen fallback is `other`](product-intent.md#why-a-particular-fallback-category); global categories classify expenses                        | Hardcoded categories include `other`; category rows are not integrated or seeded                                  | target decided | [Expense service](../server/src/modules/expense/service.ts), [category schema](../server/src/modules/category/schema.ts)                                                                                    |
| Refresh sessions and logout       | [Current-session logout](product-intent.md#why-a-particular-logout-scope) revokes the associated refresh session; access JWTs expire naturally | Session-based refresh and logout are wired     | target decided | [Auth use case](../server/src/modules/auth/use-case.ts), [logout controller](../server/src/modules/auth/controllers/http/logout.ts)                                                                           |
| Access-token lifetime             | 5-minute target                                                                                       | Default is 5 minutes; configuration can override it                                                              | target decided | [Configuration schema](../server/src/pkg/env/index.ts), [token signing](../server/src/modules/auth/service.ts)                                                                                              |
| Refresh-token lifetime            | 2-hour idle window with a 24-hour absolute cap for web                                                | Defaults are 2 hours idle and 24 hours absolute; cookies are bounded by session expiry.          | target decided | [Configuration schema](../server/src/pkg/env/index.ts), [cookies](../server/src/pkg/cookies/index.ts)                                                                                                       |
| Deleted users during refresh      | Deleting a user cascades to their refresh sessions                                                   | Session foreign key cascades user deletion                                                              | target decided | [Session schema](../server/src/modules/session/schema.ts)                                                                                                                                                       |
| Validation responses              | Shared error schema specifies `{success, message, error}` with string fields                                                                   | Validation responses differ from the declared shared envelope     | open           | [Shared schema](../server/src/shared/response.schema.ts), [login route](../server/src/modules/auth/controllers/http/login.ts)                                                          |
