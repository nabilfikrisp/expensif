## Verification

- After replacing literal application table/column names in test SQL with Drizzle schema references, all 83 tests across 16 files passed, including shared cleanup and lock-wait expiry. Typecheck, lint, and formatting passed with the existing unused expense-service `db` warning.
- After mirroring source folders under `test/modules/` and `test/pkg/`, all 83 tests across 16 files and the relocated standalone bot startup check passed. Typecheck, lint, and formatting passed with the existing unused expense-service `db` warning.
- After splitting linked-account HTTP tests by endpoint and moving cascade coverage to user deletion, all 11 tests across the three affected HTTP suites passed.
- After the maintainer changed burning to revocation, all 17 linking-use-case and key-consumption tests passed. Coverage verifies unchanged usage timestamps, repeated burning, rejection of burned keys, and preservation of existing links. Typecheck and lint passed for the changed code.
- All 80 tests across 15 files passed against the dedicated PostgreSQL test database on 2026-11-06. Setup applied committed migrations; no schema was generated or pushed.
- HTTP ownership audit found no cross-user access path in mounted resource endpoints. User identity comes from verified access tokens; API-key and linked-account mutations filter by owner and resource ID. Existing API-key tests and the new [linked-account HTTP tests](../server/src/test/modules/linked-account/) cover isolation. Expense HTTP endpoints do not exist yet; this audit does not verify future expense behavior.
- The [standalone bot check](../server/src/test/pkg/bot/telegram/start.check.ts) passed: rejected startup exits with code 1 even with an active handle; intentional shutdown cancellation does not. The report's startup divergence is resolved.
- [Auth routes](../server/src/modules/auth/controllers/http/index.ts) now map `UserError`; the [missing-user regression](../server/src/test/modules/auth/controllers/http/me.test.ts) verifies 404 instead of 500. The report's unmapped-error finding is resolved.
- One runtime request submitted an empty JSON object to the login route through the shared test app. It returned HTTP 400 with the validation shape recorded above. This was an in-process request, not a live deployment check.
- Typecheck, lint, and formatting passed. Lint retains the known unused expense-service `db` warning, deliberately accepted in [architecture](architecture.md#known-exceptions).
- The remaining report spot-checks were source inspections, not live Telegram or LLM calls. Passing tests do not cover the gaps above. The old report/evidence bundle is not present; these findings were verified from the available sources and current code.
