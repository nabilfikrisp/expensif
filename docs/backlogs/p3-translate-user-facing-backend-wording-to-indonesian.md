# Translate user-facing backend wording to Bahasa Indonesia

Problem: User-facing backend messages include English wording. API messages, validation messages, and Telegram replies need consistent Bahasa Indonesia wording.

Evidence: English messages appear in [authentication responses](../../server/src/modules/auth/controllers/http/change-password.ts), [API-key responses](../../server/src/modules/api-key/controllers/http/generate.ts), [HTTP boundary responses](../../server/src/pkg/http/index.ts), [rate-limit responses](../../server/src/pkg/http/rate-limit.ts), [Telegram expense replies and account checks](../../server/src/modules/expense/controllers/bot.ts), and [bot registration](../../server/src/app.ts).

Done when:

- User-facing API success and error messages use consistent, natural Bahasa Indonesia, including handled domain errors, authentication failures, rate limits, and HTTP boundary errors.
- Validation messages returned to users use Bahasa Indonesia, including messages generated by validation libraries.
- Telegram welcome messages, command instructions, linking messages, progress messages, expense result labels, and failure replies use Bahasa Indonesia. User-provided content remains unchanged.
- Telegram expense dates include the Indonesian weekday and full month name, for example `Tanggal: Rabu, 11 November 2026` for `2026-11-11`. Formatting preserves the expense's calendar date regardless of the server timezone; underlying date values and API date formats remain unchanged.
- API field names, machine-readable error codes, routes, HTTP statuses, Telegram command names, and response structures remain unchanged.
- OpenAPI message examples match the translated wording where applicable; technical descriptions remain in English.
- Existing behavioral checks are updated for translated messages and cover representative API success, handled failure, validation, HTTP boundary, and Telegram flows. Routine checks remain free of paid LLM calls.
- Expense reply checks verify the weekday and full month name, including preservation of the calendar date across server timezones.
- Relevant checks and `pnpm --dir server lintformat` pass. Any database-backed tests run only through the test runner against the dedicated test database.

Scope: User-facing backend wording only. Logs, code identifiers, repository documentation, LLM prompts, and user-provided content remain in their existing language. Multiple-language selection, frontend translation, unrelated error-handling changes, and database migrations are outside this item.
